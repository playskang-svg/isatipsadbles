# 지식인 답변 에이전트 운영 기준 v1.0

- 상태: `ACTIVE`
- 적용일: `2026-09-07`
- 상위 기준: `docs/ISATIPS_AI_MASTER_OPERATING_INSTRUCTION_v1.0.md` (충돌 시 상위 문서가 이긴다)
- 도구: `npm run kin -- <명령>` / `scripts/jisikin/`

네이버에서 키워드를 조회해 지식인 질문을 찾고, 그 질문에 실제로 답이 되는 답변을 쓰고,
사이트에 관련 글이 있으면 자연스럽게 연결하고, 없으면 글을 만들어 발행한 뒤 연결한다.

---

## 0. 경계 — 등록은 자동화하지 않는다

네이버 지식인 운영정책은 자동 생성·자동 등록 답변과 홍보성 링크를 금지한다.
걸리면 계정 정지에서 끝나지 않고 **`isatips.adbles.com` 자체가 스팸 도메인으로 분류될 수 있다.**
지금 막 노출이 잡히기 시작한 단계에서 그건 사이트를 잃는 일이다.

그래서 이 에이전트는 이렇게 나눈다.

| 단계 | 실행 |
|---|---|
| 검색 · 질문 수집 · 매칭 · 근거 추출 | 자동 |
| 답변 초안 작성 · 가드레일 검사 | 자동 |
| 새 글 작성 · 검증 · 배포 | 자동 |
| 화면에 띄워 보여주기 | 자동 |
| **답변 등록 버튼** | **사람 승인** |

승인 없이 등록하지 않는다. 사용자가 "등록해"라고 말한 그 질문 하나에만 해당하며, 다음 질문으로 넘어가지 않는다.

---

## 1. 실행 환경 — 먼저 확인한다

**세션에 따라 네이버 접근 가능 여부가 갈린다.** 2026-09-07 확인 결과, Claude Code 데스크톱 앱
세션에서는 `search.naver.com`·`kin.naver.com`이 세 경로 모두에서 막혀 있었다.

| 경로 | 결과 |
|---|---|
| 크롬 확장 (`mcp__claude-in-chrome__*`) | `This site is not allowed due to safety restrictions` |
| 인앱 브라우저 (`mcp__Claude_Browser__*`) | `blocked by policy` |
| `WebSearch` / `WebFetch` | 네이버가 Anthropic 크롤러를 차단 |

그래서 **모드를 먼저 판정한다.** `kin.naver.com`으로 한 번 이동해 보고 갈라진다.

### A. 브라우저 모드 (네이버가 열릴 때)

로그인된 실제 크롬을 쓴다. 인앱 브라우저에는 네이버 세션이 없다.
2단계부터 순서대로 진행한다.

- 자격증명을 다루지 않는다. 로그인은 이미 되어 있어야 한다.
- 아이디·비밀번호를 대신 입력하지 않는다.
- 캡차가 뜨면 멈추고 사용자에게 넘긴다.

### B. 붙여넣기 모드 (네이버가 막혔을 때 — 기본값으로 가정하지 말고 확인 후)

**막혔다고 작업을 멈추지 않는다.** 사람이 하는 일은 두 가지로 줄이고 나머지는 그대로 자동이다.

사용자에게 이렇게 요청한다.

> 네이버에서 `<키워드>`를 검색해 지식인 질문 하나를 열고,
> **질문 URL과 본문 전체**를 붙여넣어 주세요. (제목만 말고 본문까지)

받으면 3단계(질문 재확인)부터 8단계까지 평소대로 돈다. 매칭·근거추출·작성·검사·기록이 전부 동작한다.
마지막에 완성된 답변을 그대로 복사할 수 있게 내어주고, 등록은 사용자가 한다.

이 모드에서는 2단계의 "지식인 블록 유무 판단"과 7단계의 "화면 표시"를 사용자가 대신한다.
그 외 규칙(§3 작성 규칙, 가드레일, 카덴스, 중복 차단)은 하나도 완화하지 않는다.

## 2. 파이프라인

### 1단계 — 키워드 정하기

`npm run kin -- status`가 우선 키워드를 출력한다. 기본값은 **네이버 서치어드바이저에서 이미 노출이 잡힌 키워드**다.

노출이 있는데 클릭이 0이라는 것은 색인은 됐고 순위가 낮다는 뜻이다.
같은 주제의 지식인 답변은 (1) 직접 유입을 만들고 (2) 그 주제에 대한 사이트 신호를 보탠다.
노출조차 없는 새 키워드보다 여기가 먼저다.

목록은 `data/jisikin-config.json`의 `targetKeywords`에서 고친다.

### 2단계 — 네이버에서 조회

크롬에서 `https://search.naver.com/search.naver?query=<키워드>`를 연다.
`read_page`로 결과를 읽고 **지식인 블록이 있는지** 본다.

- 지식인 결과가 없으면 그 키워드는 건너뛴다.
- 있으면 질문 링크를 모은다. `kin.naver.com/qna/detail.naver?...docId=...` 형태다.

우선순위:

1. 답변이 아직 없는 질문
2. 답변이 있지만 질문자의 조건에 답하지 못한 질문
3. 최근 질문 (오래된 질문은 질문자가 이미 이사를 끝냈다)

채택된 답변이 이미 있고 내용이 충실하면 건너뛴다. 그런 질문에 답해봐야 읽히지 않는다.

### 3단계 — 질문 재확인 (건너뛰지 않는다)

질문 페이지를 열어 **본문 전체와 이미지까지** 읽는다. 제목만 보고 쓰지 않는다.

읽고 나서 다음을 말로 정리한다.

- 질문자의 상황: 지역, 주거 형태, 층수, 엘리베이터 유무, 짐의 양, 일정, 예산
- 이미 정해진 것과 아직 못 정한 것
- 질문자가 **이미 배제한 선택지** — 여기에 답하면 바로 삭제당한다
- 진짜 묻고 있는 것 (제목과 다를 때가 많다)

`npm run kin -- check`가 이 조건들이 답변에 실제로 들어갔는지 기계적으로 검사한다.
질문에 적힌 조건을 다루지 않으면 등록이 막힌다.

### 4단계 — 사이트 매칭

```bash
npm run kin -- match --q "<질문 제목 + 핵심 내용>" --url "<질문 URL>"
```

발행글 624건 전체에서 후보를 뽑고 판정과 답변 근거를 함께 준다.

| 판정 | 뜻 | 할 일 |
|---|---|---|
| `covered` | 기존 글로 답변 가능 | 5단계로 |
| `weak` | 관련 글은 있으나 의도가 어긋날 수 있음 | 직접 판단. 기존 글 강화가 먼저다 |
| `uncovered` | 새 글 필요 후보 | 6단계로 |

**판정은 보조 신호다.** 최종 판단은 상위 기준문서 §4·§5로 한다 —
키워드가 다르다는 이유만으로 새 글을 만들지 않는다.

이미 답변한 질문이면 `duplicate`가 뜬다. 두 번 답하지 않는다.

### 5단계 — 답변 작성

§3의 작성 규칙을 따른다. 초안을 파일로 저장하고 검사한다.

```bash
npm run kin -- check --q "<질문 원문>" --file <초안 경로> --article <슬러그> --url "<질문 URL>"
```

`등록 불가` 항목이 하나라도 있으면 고쳐서 다시 돌린다.

### 6단계 — 새 글이 필요할 때

지식인 답변을 붙일 자리를 만들려고 글을 쓰지 않는다. 상위 기준문서 §5의 사전검사 6단계를
먼저 통과해야 하고, §20의 다섯 질문에 모두 YES여야 쓴다. 아니면 그 질문은 링크 없이 답만 달거나 건너뛴다.

쓰기로 했다면:

1. **`lib/kin-generated-articles.ts`에 `Article` 객체를 추가한다.** 에이전트가 만든 글은
   수기 작성 글과 분리해 둔다. 나중에 성과를 따로 볼 수 있고, 문제가 생겼을 때 한 파일만 되돌리면 된다.
   (지역 트리에 묶여야 하는 글만 예외적으로 해당 지역 파일에 넣는다)
2. `lib/internal-links.ts`의 `curatedLinks`에 앞뒤 연결을 넣는다 — 고립된 글을 만들지 않는다
3. 일반 글이면 `scripts/seo-audit.mjs`의 `articles` 배열에 슬러그를 추가한다
4. 검증하고 배포한다

```bash
npm run lint
npm run ship -- -m "feat(content): <글 제목>"
```

5. **배포가 끝나고 실제로 열리는 것을 확인한 뒤에** 답변에 링크를 넣는다.
   404를 지식인에 올리면 그대로 신고 사유다.

### 7단계 — 보여주고 승인받기

브라우저 모드면 크롬에서 질문 페이지의 답변 입력창까지 이동해 **초안을 보여준다.**
붙여넣기 모드면 답변 전문을 그대로 복사할 수 있게 코드블록으로 내어준다.

어느 쪽이든 그 상태로 멈추고 사용자에게 묻는다.

> 이 답변을 등록할까요?

명확한 승인을 받은 뒤에만 등록한다. 등록 후 기록한다.

```bash
npm run kin -- record --url "<질문 URL>" --article <슬러그> --q "<질문 원문>" --file <초안 경로>
```

기록해야 중복 답변과 템플릿 검사가 동작한다.

`data/jisikin-log.json`은 **`.gitignore`에 있다.** 질문자의 주소·일정·짐 목록과 답변 본문이 담기고,
저장소가 공개라 커밋하면 git 히스토리에 영구히 남는다. 지식인 활동 기록이 공개되는 것 자체도
스팸 분류 위험을 키운다. 로그는 실행하는 맥에만 둔다.

## 3. 답변 작성 규칙

### 링크가 없어도 완결된 답변이어야 한다

읽는 사람이 링크를 누르지 않아도 궁금증이 풀려야 한다.
"자세한 건 링크에서 보세요"는 홍보성 답변으로 신고당하는 전형이다.

링크를 걷어낸 본문이 **최소 300자**여야 한다. 검사가 막는다.

### 질문자 한 사람에게 쓴다

3단계에서 정리한 조건 — 지역, 층수, 엘리베이터, 짐, 일정 — 을 답변 안에서 직접 받는다.

> "3층에 엘리베이터가 없으면 사다리차를 쓸지 계단으로 옮길지가 먼저 갈립니다."

이렇게 쓰면 질문자가 자기 얘기라고 느낀다. 일반론만 쓰면 지운다.

### 결론부터 쓴다

첫 문장에서 답한다. 배경 설명·인사·자기소개로 시작하지 않는다.
질문을 다시 옮겨 적지 않는다. 검사가 잡는다.

### 템플릿처럼 보이지 않게

매번 같은 틀로 쓰면 답변 몇 개만 쌓여도 봇으로 잡힌다. 검사가 이전 답변과의
글자 4-gram 유사도를 재서 **32% 이상이면 경고, 50% 이상이면 등록을 막는다.**
첫 문장이 이전 답변과 같아도 막는다.

같은 주제라도 매번 다르게 접근한다.

- 어떤 답변은 비용 구조부터, 어떤 답변은 실패 사례부터, 어떤 답변은 순서부터
- 길이를 고정하지 않는다. 짧게 끝나는 질문은 짧게 답한다
- 소제목·번호매기기를 매번 쓰지 않는다. 문단 세 개로 충분한 질문이 많다
- 다음 상투구는 반복하지 않는다: "도움이 되셨으면", "참고하시기 바랍니다",
  "정리하자면", "자세한 내용은", "좋은 결과 있으시길"

### 정말 도움이 되는 말만 쓴다

한 문장도 채우기 위해 쓰지 않는다. 문장마다 질문자가 그걸 읽고 무엇을 할 수 있는지 답할 수 있어야 한다.

지운다:

- 인사, 자기소개, "질문 잘 읽었습니다" — 검사가 막는다
- "이사는 준비할 게 많습니다" 같은 누구에게나 하는 서두
- "업체마다 다릅니다"로 끝나는 문장. 다르다면 **무엇에 따라** 다른지까지 쓴다
- 질문자가 이미 아는 내용

검사가 구체 정보(숫자·층·엘리베이터·견적서·계량기 같은 판단 가능한 대상)가 없는 문장 비율을 재서
절반을 넘으면 경고한다. 경고가 뜨면 문장을 늘린 게 아니라 덜어내야 한다는 뜻이다.

짧아도 된다. 세 문단으로 끝나는 답변이 열 문단짜리 일반론보다 채택된다.

### 모르는 것은 쓰지 않는다

상위 기준문서 §7이 그대로 적용된다. 가격·정책·법률·절차·업체 정보는 확인한 것만 쓴다.

금액은 단정하지 않는다. 쓴다면 무엇에 따라 달라지는지와 함께 쓴다.
검사가 금액·비율 표현에 조건 단서가 없으면 경고한다.

### 링크는 하나, 그리고 본문 안에서 자연스럽게

- 답변당 사이트 링크 **1개**. 검사가 막는다
- **제휴 링크는 절대 넣지 않는다.** 숨고·쿠팡·텐핑 링크를 지식인에 직접 올리면 홍보 답변이다.
  제휴는 사이트 글 안에 있고, 지식인에서는 사이트 글로만 연결한다. 검사가 막는다
- 링크는 맨 끝에 툭 붙이지 말고, 답변에서 다룬 내용을 이어가는 자리에 넣는다

> "엘리베이터 예약과 사다리차 조건을 어떻게 비교하는지는 정리해둔 게 있어서 같이 남깁니다. <URL>"

- 답변한 내용과 링크한 글의 주제가 실제로 이어져야 한다

---

## 4. 카덴스

하루 **3건**이 기본값이다 (`data/jisikin-config.json`의 `dailyAnswerLimit`).
검사가 한도를 넘으면 막는다.

새 계정으로 갑자기 여러 건을 올리는 것이 봇 판정의 대표 신호다.
많이 다는 것보다 채택되는 답변 하나가 낫다.

## 5. 검사 항목 한눈에

`npm run kin -- check`가 보는 것. 등록 불가는 하나만 걸려도 멈춘다.

| 항목 | 기준 | 결과 |
|---|---|---|
| 링크 뺀 본문 | 300자 이상 | 미달 시 등록 불가 |
| 링크 개수 | 답변당 1개 | 초과 시 등록 불가 |
| 제휴 도메인 | 숨고·쿠팡·텐핑·링크프라이스 등 | 포함 시 등록 불가 |
| 질문자 조건 | 질문에 적힌 조건을 다루는가 | 미반영 시 등록 불가 |
| 조건별 해결책 | 엘리베이터 없음 → 사다리차·계단·인력 중 하나 | 누락 시 등록 불가 |
| 인사·서두 | "안녕하세요", "질문 잘 읽었습니다" | 포함 시 등록 불가 |
| 채택 구걸·맺음 인사 | "채택 부탁드립니다", "좋은 하루 되세요" | 위치 무관 등록 불가 |
| 이전 답변 유사도 | 글자 4-gram | 32% 경고 / 50% 등록 불가 |
| 첫 문장 반복 | 이전 답변과 동일 | 등록 불가 |
| 정보 밀도 | 구체 정보 없는 문장 비율 | 절반 초과 시 경고 |
| 금액·비율 | 조건 단서 유무 | 단서 없으면 경고 |
| 카덴스 | 하루 3건 | 초과 시 등록 불가 |
| 중복 | 같은 질문 재답변 | 등록 불가 |

매칭에는 **특수 품목 배제**가 걸려 있다. 질문이 특정 품목(에어컨·도어락·식기세척기 등)을 지목하는데
후보 글이 그 품목을 다루지 않으면 점수를 0으로 만든다. 일반 글을 특수 질문에 억지로 붙이지 않기 위해서다.

## 6. 하지 않는 것

- 승인 없이 등록
- 같은 질문에 두 번 답변
- 제휴 링크를 지식인에 직접 게시
- 확인하지 않은 금액·정책·법률 서술
- 링크로 보내기 위한 껍데기 답변
- 답변 자리를 만들려고 글을 발행하는 것
- 캡차 우회, 자동 로그인, 계정 여러 개 사용
- 배포 확인 전에 링크 게시
